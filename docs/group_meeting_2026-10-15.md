## 0. 项目一句话

在仿真里生成「拾取热物体」任务的数据集：RGB + 本体感受之外，额外提供**触觉**（指尖弹性体形变场）
与**温度**（指尖 + 物体温度场）两条物理通道，供外部训练/评测语言条件 VLA、做通道消融、
以及热物抓取的成功率评测。**本项目只生成数据与工具，不训练策略**（训练在外部进行）。

### 三条关键结论（如果只记三件事）

1. **管线与「抓起来 → 靠指尖温度判材质 → 放对地方」的任务链已经全程跑通，且每一步都有实测证据**：
   盲判复算 32/32、三材质 20 抓 0 错、三个数据集文件 3/3 成功、validator 0 issues。
2. **判据的物理含义清楚，窗口还能再压**：升温率 λ ∝ 接触有效导热 `k_eff`，与物体冷热无关
   （同一阈值同时覆盖热件与冷件）；本周把判定窗口从 4.0 s 压到 **1.5 s**
   （判定时刻 `t2+4.15 s` → `t1+1.65 s`），每个候选省 **2.50–3.10 s**，窗口占一个候选的比例从 82% 降到约 60%。
3. **最大的缺口不是算法，是数据本身**：全量数据集还没有生成过一次（仓库内现有 3 集预览）。
   在 M9 跑完之前，没有任何下游训练可以开始。

### 1.2 两条物理通道的保真度（本阶段的主要发现）

**触觉**
- 表征 = 每指 63 个 3D 位移标记（9×7，间距 2.03 × 1.54 mm，覆盖 14.2 × 13.8 mm 指垫）
  + 由它重采样出的 64×64 height map（语义 = UniVTAC 的 `press_depth`，不增加信息）。
- 已知缺陷 **R25**：弹性核宽度随网格间距变宽 —— 同一抓取，16×16 场峰值 27.4 / 36.0 µm，
  改到 9×7 只剩 5.8 / 7.9 µm（**~22%**）。形状信号因此被抹成宽穹顶。
  **已定案（2026-10-08，§9-R25）：接受核宽展宽、不重标核**（重采样试验预测 26.3/36.0 µm ≈ 原值 ⇒ 掉幅值的是核宽）；
  需要绝对幅度时用 16×16 旧 config。这是触觉保真度的主要已知代价。
  图：`figures/tactile_field_and_map.png`（场与 height map）、`figures/kernel_grid_coupling.png`（R25 缺陷本身）。

**温度** —— 三轮修正把「指尖温度能不能分辨材质」从 1.03× 提到 ~2×：
1. `k_pad` 0.02 → **0.25**（真实硅胶值，R35）：原来 `k_eff` 被指垫卡死，铝和钢的指尖读数**逐位相同**；
2. 指尖通道定案（R36）：官方最粗单格 `(1,1,1)` + 官方 RC 0.05 s / 白噪 0.05 °C / 量化 0.1 °C，只录 measured；
3. 接触面积口径补丁 `pad_face`（R33/R37）：引擎在接触点 <3 个时把穿透深度当半径（面积错 24–36×），
   换成指垫面均分 `Aᵢ = A_face/√nᵢ` 后 `ΣAᵢ²` 恒定、与求解器报几个接触点无关。
   副作用实测：引擎的「冻结过冲」伪迹 **17/64 指（26.6%）→ 0/64**。

物体侧通道另有一条可用信号：全网格温度 spread 跨材质 **159–321×**（与 1/α 严格反序）——金属/非金属可分。
图：`figures/thermal_channel.png`、`figures/material_thermal_contrast.png`。

### 1.3 判材质任务链（本阶段主线）

**`pick_by_temperature`（R38）**：桌上两块外观完全相同的方块（一金属一非金属），每回合槽位置换；
专家抓起来，在抓取过程中读指尖温度曲线判材质组，判错就把方块放回去换另一块。
- 判据 = 接触后升温曲线的指数率 λ̂。**一个阈值 1.04 同时覆盖热件与冷件** —— λ 里没有温度。
- 盲判复算 **32/32 正确**，实测两组分离 **2.17×**。
- 图：`figures/material_judge.png`。

**`put_in_tray`（R39，当前任务）**：桌上五块**随机颜色、随机边长（30–65 mm）**的立方体
（2 铁 + 2 木 + 1 塑），桌边一个托盘；指令「把 X 质的立方体放进托盘」，三条指令各出一个文件。
- 三材质是**先算后选**的：λ 只通过 `k_eff = 2k_pad·k/(k_pad+k)` 感知物体，而「木 vs 塑」这类双低材料对的
  真实 `k_eff` 比只有 1.1–1.2×（材料本身的分辨率上限，窗口和传感器都修不了）
  ⇒ 取 **铁 k=80 / 尼龙 k=0.25 / 巴尔沙木 k=0.055**，`k_eff` = 0.498 / 0.250 / 0.090，相邻 **1.99× / 2.77×**。
- 定标（20 抓）：λ̂ = **0.278 / 0.734 / 1.484**，相邻分离 **2.64× / 2.02×**；
  两条边界取最坏情况几何中点 **0.50 / 1.04**，实测 **0 错 / 20 抓**。
- 反捷径：颜色（每次 build 重抽）、槽位（每回合置换）、试的顺序（候选顺序随机）三条全部堵上；
  「只看不摸」（读接触前物体温度网格）**没堵** —— 如实记账，相邻最坏分离 1.22×（比 R38 的 4.04–4.35× 窄得多，
  但确实存在）。
- 交付预览：`datasets/v1.5/hdf5/put_in_tray_{iron,wooden,plastic}.{hdf5,mp4}`，
  3/3 成功、validator 0 issues、**8 次抓取判定全部正确** ——
  其中 5 次是「候选材质不对 → 放回去换一块」的重试（专家从未判错材质本身）。
  三个文件的步数（iron / wooden / plastic）= **654 / 189 / 456**。

**判定窗口 4.0 → 1.5 s（R40，本周新增）** —— 起因：「接触判断时间过长」。
- 把代价拆开：一个候选里，窗口占 **82%**（`t2 → 判定` 4.15 s）。
- 两条杠杆：
  - **换估计量**（`sim/expert/thermal_judge.py::ratio`）：引擎的接触响应是 `dT/dt = λ(T_cell − T(t))`，
    `T_cell` 只是斜率的**尺度** ⇒ 在两个半窗斜率的**比值**里直接消掉：
    `λ = ln(s1/s2)/Δt`。**参数不用估，窗口就只剩「装得下两个可分斜率」一个要求**（原来 `fit`
    要估 `T_cell`，小窗口里 `T_cell` 和 λ 分不开，所以被迫用 4 s）。
  - **窗口锚点前移**：从**先碰上的那个指垫**起算，而不是等后碰的那个（带一个闸门旋钮保证后手仍有足够采样）。
- 实测（旧文件反事实复算，同一批 8 抓）：三条带不变、**8/8 分带正确**，
  每候选省 **2.50–3.10 s**。`W = 1.0` 被否掉：不是信号问题，是**采样数悬崖**
  （后手只剩 9 个采样 < 下限 10 ⇒ 丢掉 4/16 个指尖）；`W = 1.5` 反而比 `W = 1.0` 更快（`t1+1.65` vs `t1+1.75` s）。
- 阈值**不动**（0.50 / 1.04）：新中点 0.45 / 1.06 只多约 1% 余量，而 1.04 是 R38 共用的数。
  **这是判断，不是测量。**
- 兼容性：新闸门默认关闭 ⇒ `pick_by_temperature` 及其余任务**逐位不变**（已逐配置核对）。

### 2.2 关键缺口（按「卡不卡下游」排序）

1. **全量数据集不存在**（最硬的一条）。当前仓库内只有 `put_in_tray` 的 3 集预览。
   M9（多材质 × 50 集 @ 256²）按 preview 外推约 **~430 MiB / 1–1.5 h 墙钟**（以最终任务集为准），
   是**一切下游训练的前提**。
2. **`put_in_tray` 这三个文件本身也要重生成**：它们跑在旧判定协议上，且带着一个已修但尚未重跑的缺陷
   —— 三个文件的回合随机流是同一条 ⇒ 每回合的槽位置换三份完全相同，
   **「位置不能代表材质」这条反捷径实际没生效**（已修，文件待重跑）。
3. **触觉幅值仅相对量、真机对齐未做**（R25/M11）：场结构对、幅值约 22%；核宽已定案接受（不重标核，需绝对幅度用 16×16 旧 config）。与真机 gsmini（与 UniVTAC 同族）的对齐未做。
4. **温度幅值是相对量**（R14/R16）：全项目绝热 + 接触热增益由 `gs.EPS` 支配，**绝对升温率不可信**。
   要么把 EPS 依赖量化成换算表，要么等真机热电偶标定。
5. **融合基线未开始**：「温度和触觉对策略到底有没有用」目前没有实测答案 —— 这是任务链跑通后的下一件大事。
6. **任务套件收尾（M4）**：replay/analyze 工具、数据卡。
7. **验证方法**：现有校验全部是「自洽性」（sim 对 sim），没有真值对标；温度通道还缺物理性 validator 规则。
