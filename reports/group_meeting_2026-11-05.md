# 组会汇报：热触觉识别任务闭环评测与失败诊断

**日期**：2026-11-05  
**本周主题**：π0.5 + LoRA 策略的闭环评测；抓取失败原因定位  
**产出**：评测诊断结论 + 重跑方案（本周未改动代码/数据，全部为只读分析）

## 1. 本周工作概述

- 对 `experiment/runs/lemon_cont2` 的 4 个 episode（seeds 1000–1003，每集 400 步，0/4 成功）做逐帧诊断。
- 回答三个具体问题：
  1. 夹爪接触物体后为什么不再继续闭合；
  2. 示教抓取是否本身就是“两段式”、数据是否有问题；
  3. 评测中的夹爪是否撞到了桌子。
- 结论：**评测配置与预期不一致是首要问题**；策略的下探/闭合时机、位置控制下的夹持力、失败后的恢复行为是三个直接原因；示教本身正常。

## 2. 实验设置

- 任务：`pick_cold_can` / `pick_lemon`，7 个物体，`place_in_tray`；温度档按 `temperature_groups: [[0,1,4]]` 每集置换。
- 策略：π0.5 + LoRA（openpi JAX，云端 AutoDL 训练），Genesis 闭环评测（`experiment/eval_closed_loop.py`）。
- 本次 run：`lemon_cont2`，4 集，seeds 1000–1003，400 步/集，连续夹爪（`binary_gripper=false`），全部失败。

## 3. 主要发现

### 3.1 首要问题：评测实际跑的是 cold-can 配置，不是柠檬配置

`records.jsonl` 的证据：

- 指令是 “Pick up the colder can...”“Among the cans...” 等，属于 `pick_cold_can.yaml` 的模板（`seed % 12`）；
- `target_material = aluminum`，`target_temp_c` 在 −13.5 … +0.9 °C（罐子的 [−18, 4] 区间）；
- 策略的 TCP 却走向柠檬槽位 (0.52, −0.20)，而不是冷罐槽位 (0.30, −0.20)；指尖温度升到 24–25 °C，对应 cold-can 场景里 25 °C 的柠檬。

原因：`eval_closed_loop.py` 的 `--config` 默认值是 `pick_cold_can.yaml`，运行命令没有显式覆盖。因此本轮 0/4 **不能作为柠檬任务的评测结果**，需要重跑。

> 策略行为与“柠檬任务”一致，但训练分布仍需查 checkpoint / 训练记录确认；本轮只能说明行为，不足以证明训练任务。

### 3.2 接触后夹爪为什么不再闭合：位置控制 + 偏心接触/滑移

- 控制器是位置控制：`finger_target` 是位置设定点，指力 = `kp · (target − q)`，`kp = 100 N/m`。q = 0.026 时误差 2.6 cm → 每指约 2.6 N；q = 0.0205 时约 2.05 N。`finger_force_max = ±100 N` 根本达不到，**PD 刚度才是真正的限力环节**。
- 遇到刚性物体时 q 会停在物体宽度上，只有物体屈服/滑移时手指才继续动；示教的 q 同样停在 0.01845，对应 2q ≈ 3.7 cm 的柠檬短轴间隙。
- 本轮的问题在**闭合位置偏心且偏低**：TCP 距柠檬中心 1–3 cm，一个垫先碰到柠檬并把它推开；q 停在约 0.026（5.2 cm 间隙，接近柠檬长轴，不是短轴 3.7 cm）。随后柠檬滑移/转动；一旦脱出，q 迅速掉到接近 0（空夹）：
  - ep0：q 0.026 → 0.0066（step 140）
  - ep2：q → 0.0029（step 100）
  - ep3：q → 0.0005（step 100），step 150 再次夹到柠檬（q 0.0213），仍未成功。
- 策略在闭合阶段还有 `a[6]` 的符号抖动（重新打开）；连续/二值映射在饱和步上等价，本轮是连续模式，抖动不是映射差异。

### 3.3 示教抓取是否也是“两段式”：命令层面不是，数据没有问题

- 示教的**命令**从 CLOSE 到 LIFT/HOLD/CARRY 一直是 `grip = +1`，只有 DROP/RELEASE 用 −1；没有中途重新打开。
- 示教的 **q 曲线**看起来像两段，是因为：
  - PD 先快后慢；
  - 接触后停在柠檬宽度（q ≈ 0.0185，2q ≈ 3.7 cm）；
  - `squeeze_steps = 10` 的保持段；
  - CLOSE 的触发是 3D 距离 < `descend_tol_m = 0.015 m`，不是单一 z 阈值。
- 柠檬示教统计：TCP 最低 0.41404（= 柠檬中心），q 最低 0.01845（= 短轴），抓取居中；cold-can 1.6 语料 50/50 生成成功、validator 0 issues。
- **结论：示教本身正常；策略的提前闭合、偏低、偏心是额外问题，不是从示教继承的。**

### 3.4 夹爪是否撞桌：是，指尖垫下缘浅擦/压桌（ep0 明显，ep3 擦边）

- 桌面 z = 0.4000；Panda 指垫下缘比 TCP 低 7.4 mm（手指关节 0.0584 + 指垫 slab 到 0.054 = 0.1124 vs TCP 0.105）。
- 逐点对照：

| Episode | 最低 TCP z（step） | 指垫下缘约 | 与桌面间隙 | 判定 |
|---|---|---|---|---|
| ep0 | 0.40710（57） | 0.3995 | −0.5 mm | 轻擦/压桌 |
| ep3 | 0.40790（60） | 0.4005 | +0.5 mm | 擦边 |
| ep1 | 0.40912（159，抽查） | 0.4017 | +1.7 mm | 未碰 |
| ep2 | 0.41153（60） | 0.4041 | +4.1 mm | 未碰 |
| 示教 | 0.41404 | 0.4066 | +6.6 mm | 未碰 |

- 行为佐证（ep0 step 55–66）：实测 TCP z 卡在 0.4071–0.4075，而 `cmd_pos` 的 z 目标每步高 1–4 mm；IK 残差 < 0.4 mm；夹爪指令已全闭，q 却只从 0.037 缓慢降到 0.033、之后停在 0.026；指尖温度同时从 21.1 升到 22–23.5 °C（柠檬接触）。也就是**垫下缘蹭桌 + 垫面碰柠檬同时发生**。
- 限制：trace 不记录 contact flag/接触力，eval 也没把场景里的 `link_contacts` 写进 trace；“撞桌”是几何 + 卡住行为推断。可从 `videos/ep00_seed1000.mp4`（step 55 ≈ 2.8 s）和 `videos/ep03_seed1003.mp4`（step 60 = 3.0 s）确认。
- 对比：示教的指垫下缘离桌 6.6 mm；本轮策略比示教多下探约 7 mm，正好把垫角送到桌面。

### 3.5 失败后的恢复行为（附加问题）

- 失败后策略给出 `a[2] ≈ 0.9–1.08`（每步 +4.5–5.4 cm），TCP 被推到 z 1.05–1.16 m；`ik_pos_err` 增至 0.043–0.046 m；ep2 末态姿态随机化。没有重新接近/重试，直接饱和漂移。
- 这与抓取失败是两件事：即使抓取修好，恢复策略也需要单独检查。

## 4. 结论

1. **本轮 0/4 不是有效的柠檬任务结果**：评测实际跑了 cold-can 配置，必须先修正评测配置再比较。
2. 在 cold-can 场景里，策略已经暴露出三个具体问题：
   - 下探/闭合比示教低约 7 mm，且偏心 1–3 cm；
   - 位置控制下每指只有约 2–3 N 的夹持力，叠加垫缘蹭桌，q 停在错误宽度，柠檬滑移；
   - 失败后没有恢复，直接饱和漂移。
3. **示教/数据不是根因**：示教是单段闭合、居中抓取；策略的“两段式”表现是 PD + 接触停止 + 策略抖动，不是数据缺陷。
4. 夹爪**确实轻擦桌面**（ep0 约 0.5 mm，ep3 擦边），但它是下探过低的症状，不是独立的机械故障。
